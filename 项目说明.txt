

# 高级动态相册项目

开发一个基于 **GitHub Actions + GitHub Pages** 部署的现代化高颜值在线相册网站。

项目无需传统后端服务器，所有内容均可以通过 GitHub 仓库进行管理，并通过 GitHub Actions 自动构建和部署到 GitHub Pages。网站整体视觉风格要求 **高级、现代、沉浸式、具有科技感和电影感**，避免普通的静态图片列表效果。

## 一、核心目标

打造一个具有高级视觉效果的个人在线相册，重点突出：

* 高质量图片展示
* 沉浸式浏览体验
* 丰富的动态交互效果
* 流畅的页面动画
* 响应式设计
* 自动按照照片日期排序
* 支持 PC、平板、手机
* GitHub Pages 静态部署
* GitHub Actions 自动化构建和发布
* 不依赖传统服务器或数据库

整体效果应接近现代商业摄影网站、Apple 风格作品集以及高端个人影像档案馆。

---

## 二、相册视觉设计

整体采用 **深色沉浸式设计**，以黑色、深灰、半透明玻璃效果为基础。

视觉关键词：

> Cinematic / Premium / Minimal / Futuristic / Immersive / Glassmorphism

页面需要具有明显的层次感和空间感。

### 1. 首页

首页不是简单的图片网格，而是一个具有视觉冲击力的相册入口。

可以包含：

* 全屏 Hero 图片
* 大型标题
* 当前相册照片数量
* 时间跨度
* 动态背景
* 图片缓慢缩放
* 光影粒子或渐变效果
* 鼠标移动产生轻微视差
* 页面进入动画

例如：

```text
MY PHOTO ARCHIVE

Capturing moments,
preserving memories.

2020 — 2026

128 Photos
24 Albums
```

Hero 图片可以采用全屏背景，并使用：

* Ken Burns 缓慢缩放
* 渐变遮罩
* 模糊光晕
* 玻璃质感 UI
* 淡入淡出动画

## 三、照片展示方式

照片默认按照 **日期倒序排列**：

> 最新照片 → 最旧照片

例如：

```text
2026

September
──────────────

[照片] [照片] [照片] [照片]

August
──────────────

[照片] [照片] [照片] [照片]

July
──────────────

[照片] [照片] [照片]
```

照片的日期应该是排序的核心依据。

优先从照片文件名、目录结构或图片元数据中解析日期。

建议支持以下格式：

```text
20260927001.jpg
20260927002.webp
20260927003.avif
```

原图统一平铺存放于 `public/photos/` 目录，文件名必须采用 `YYYYMMDDNNN` 格式：

* `YYYY`：四位年份
* `MM`：两位月份
* `DD`：两位日期
* `NNN`：当天照片的三位顺序号，从 `001` 开始

例如：`public/photos/20260927001.jpg`。图片扩展名可使用 `.jpg`、`.jpeg`、`.png`、`.webp` 或 `.avif`。

如果图片本身包含 EXIF DateTimeOriginal，则优先使用 EXIF 日期。

如果无法获取 EXIF，则尝试从文件名解析日期。

如果仍然无法获取日期，则使用 Git 提交时间或文件修改时间作为最后的备用日期。

## 四、时间轴式相册

照片不仅按照日期排序，还应该具有明显的时间轴视觉效果。

例如：

```text
2026
│
├── September
│   ├── 27
│   │   ├── Photo
│   │   ├── Photo
│
├── August
│   ├── 18
│   ├── 12
│
2025
│
├── December
├── October
```

年份和月份作为大型视觉分隔元素。

年份标题可以采用超大字体，并配合：

* 滚动渐入
* 视差效果
* 模糊到清晰
* 数字缓慢移动
* 滚动进度指示

让整个相册具有类似「数字影像时间轴」的感觉。

## 五、照片卡片效果

照片不要使用普通 Bootstrap 风格卡片。

采用高级 Masonry / 瀑布流布局，同时保持视觉节奏。

每张照片可以具有：

* 圆角
* 阴影
* 图片悬停放大
* 光晕
* 图片轻微位移
* 渐变遮罩
* 日期信息
* 地点信息（如果存在）
* 相册分类

鼠标悬停时：

```text
普通状态
        ↓
图片缓慢放大
        ↓
显示半透明黑色渐变
        ↓
显示日期 / 标题
        ↓
出现查看按钮
```

动画必须流畅，避免过度夸张。

## 十三、照片数据管理

照片不建议全部硬编码到网页中。

建立统一的数据生成机制。

例如：

```text
photos/
├── 20260927001.jpg
├── 20260927002.jpg
├── 20260818001.webp
├── 20251225001.jpg
│
```

照片目录不再按年份或月份分级；构建脚本应根据 `YYYYMMDDNNN` 文件名解析拍摄日期并自动生成时间轴分组。

构建时自动扫描照片目录并生成：

```text
photos.json
```

例如：

```json
{
  "photos": [
    {
      "src": "/photos/20260927001.jpg",
      "date": "2026-09-27",
      "year": 2026,
      "month": 9,
      "title": "Summer Evening",
      "album": "Life"
    }
  ]
}
```

然后前端自动按照日期进行排序。

默认：

```text
DESC
```

即：

```text
最新 → 最旧
```

同时可以提供：

```text
Newest
Oldest
```

切换。

## 十四、GitHub Actions 自动部署

项目必须提供完整的 GitHub Actions 工作流。

例如：

```text
.github/
└── workflows/
    └── deploy.yml
```

当向主分支 Push 后：

```text
Git Push
   ↓
GitHub Actions
   ↓
安装依赖
   ↓
扫描照片
   ↓
解析照片日期
   ↓
生成 photos.json
   ↓
构建网站
   ↓
生成静态文件
   ↓
部署 GitHub Pages
```

整个流程自动完成。

用户只需要：

```text
git add .
git commit
git push
```

即可更新网站。

## 十七、性能要求

虽然视觉效果需要非常炫酷，但不能牺牲性能。

目标：

* 首屏快速加载
* 图片懒加载
* 避免大型 JS
* 避免持续运行高负载动画
* 使用 CSS transform / opacity 实现动画
* 支持 prefers-reduced-motion
* 移动设备自动降低复杂动画

例如：

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

**高级、简洁、炫酷、科技感、电影感、沉浸式、流畅、现代、精致。**

## 二十、最终验收标准

完成后必须确保：

1. 可以正常运行。
2. 可以构建生产版本。
3. 可以通过 GitHub Actions 自动部署。
4. 可以正常运行于 GitHub Pages。
5. 照片默认按照日期倒序排列。
6. 可以自动识别照片日期。
7. 支持年份 / 月份时间轴。
8. 支持 Masonry 瀑布流。
9. 支持全屏 Lightbox。
10. 支持键盘和移动端手势。
11. 支持图片懒加载。
12. 支持响应式布局。
13. 支持搜索和筛选。
14. 动画流畅且具有高级感。
15. 不依赖服务器和数据库。
16. 修改或新增照片后，只需要 Push 到 GitHub 即可自动更新网站。
17. README 提供从创建 GitHub Repository 到开启 GitHub Pages 的完整部署步骤。

**重点：不要只实现功能，要把视觉设计和交互体验做到高端产品级。打开网站的第一眼应该有明显的视觉冲击力，同时保证照片本身仍然是整个网站的主角。**

“**直接创建完整可运行项目，不要只给代码片段，并自行决定合理的依赖和实现方案**”。
